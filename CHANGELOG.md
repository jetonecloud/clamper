# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

Everything below is the first release, to be tagged `v0.1.0`. Clamper makes an AWS budget enforceable: when spend crosses a limit, it stops the resources you allowed it to stop, records what they were first, tells you what it stopped and what it could not, and puts everything back with one command.

### Added

- **Eight reversible actions, declared in one file.** EC2 instances (stop/start), Auto Scaling groups (min and desired to zero, recorded sizes back), ECS services (desired count to zero and back), RDS instances and Aurora clusters (stop/start), Lambda functions (reserved concurrency to zero; back to the recorded value, or the setting removed if there was none), SageMaker notebook instances (stop/start), and Redshift provisioned clusters (pause/resume, priced per node). Every write Clamper can make is a row in [`actions.yml`](src/clamper/data/actions.yml) — fourteen boto3 methods, pinned by a test — and a row with a terminate or delete verb makes the package fail to import. The single exception, `lambda:DeleteFunctionConcurrency`, is named with its reason.
- **One write path.** Every customer-facing write goes through `Actuator.invoke`, which takes the method from the registry by action id rather than from its caller. No boto3 method name appears in the Python source at all, and [`tests/test_safety.py`](tests/test_safety.py) holds that structurally, along with: dynamic dispatch only in the actuator, every other client call a read or a pinned write to Clamper's own infrastructure, clients built in one module, no subprocess, eval or unsafe YAML, and no CLI dependency in anything the Lambda imports.
- **A write-ahead ledger on DynamoDB.** The previous state and the state Clamper will apply are recorded before the call; the outcome is settled after. A crash in between leaves `pending`, reported as "outcome unknown" and exit 2 — never as done — and the next reconcile settles it from the resource's live state. No TTL, no delete permission: the ledger is an audit log and is never pruned.
- **Target selection in a fixed order**, with a reason for everything dropped: scope, enabled type, opt-in by tag or selector, `clamper:protect` (checked last and overridable by nothing), three independent self-exclusion checks, clampable now, and the cap. Over `max_actions_per_run`, nothing is clamped at all and somebody is told.
- **The enforcer**, a Lambda woken by a Budgets alert on its own alerts topic or by an EventBridge schedule every six hours. It never parses the SNS message: it reads the spend from `DescribeBudget` itself, so a spoofed or replayed message cannot invent a breach. It settles pending entries, re-stops RDS and Aurora that AWS restarted after seven days and says so, and clamps on a real breach. Notifications go to a separate notifications topic, so the enforcer never wakes itself up.
- **Notifications** that say five things in order: what crossed, which limit, what was stopped, what was not and why, and the exact release command. Warnings only when Budgets rang; a dry run sends the same would-clamp list once a month, not four times a day. Optional Slack, with the webhook URL in SSM `SecureString` and only its name in the config.
- **`clamper release`** — one clamp, `--all`, or `--target` one resource — restoring exactly what the ledger recorded. A resource changed by hand since the clamp is a conflict and is left alone unless `--force`. Recorded identifiers and values are validated before any call is built, since the ledger is untrusted input. Release ignores `mode`, so a clamp made in enforce is always releasable, and has its own `--dry-run`.
- **The rest of the command line:** `plan` (what would be clamped, including what is protected and what Clamper found and will not touch, such as SageMaker endpoints and Redshift Serverless workgroups, which have no pause), `status`, `ledger`, `clamp` (the reconcile by hand; `--yes` overrides the cap and nothing else), `simulate` (the enforcer's own run with real reads, dry-run forced and an in-memory ledger; `--assume-breach`), `doctor` (credentials, the stack, an unconfirmed email subscription, inactive cost allocation tags, unreadable budgets, a disabled reconcile schedule, and an enforcer not built from the local `clamper.yml`), `policy`, `init`, `validate`, `version`, and `demo`.
- **`clamper deploy`**: a bootstrap stack with one locked-down bucket, the enforcer zip under a content-addressed key, then the main stack, waiting on each. `--template-only` writes both templates and the zip with no AWS calls at all, for deploying from the console. The templates are plain CloudFormation, cfn-lint clean, and CI checks them.
- **Least privilege, generated.** The enforcer's policy comes from `actions.yml`, scopes each write to the managed tag with that service's own condition key, and has no `iam:*`, `cloudformation:*`, `sts:*` or `dynamodb:DeleteItem`. A generator that refuses wildcards, destructive verbs and unconditioned writes, an operator policy for people, and a hand-written deploy policy with its own account of what it can do, all in [`iam/`](iam/README.md).
- **Reports** in terminal (plain ASCII, ordered by cost), Markdown and versioned JSON ([`docs/json-schema.md`](docs/json-schema.md)), from one report object whose counts come only from line statuses. Exit codes 0, 1 and 2, with 2 beating 1.
- **`clamper demo`**: the real plan and reconcile against bundled fixtures and a fake account, with no AWS. It shows a clamp, a paused Redshift warehouse, a refused call reported as failed, a protected resource, an excluded one, and a SageMaker endpoint and a Redshift Serverless workgroup it will not touch.
- CI on Python 3.11–3.13 with a separate safety job, a clean-install demo, cfn-lint on the generated templates and a container build; a release workflow with checksums and build provenance; a non-root container image.

### Notes

- **Hours, not cents.** AWS Budgets data refreshes up to three times a day, so a clamp happens within hours of the billing data showing a breach. Money already spent, Savings Plans, Reserved Instances, storage and support keep billing whatever is stopped. The README says so first.
- **The IAM tag-condition rows were not read from AWS's authorization tables.** The Service Authorization Reference pages render with JavaScript and could not be read directly, so the condition keys in [`docs/design.md`](docs/design.md#which-iam-actions-support-a-tag-condition) come from service-level ABAC documentation and secondary sources. A wrong row makes a permission narrower than intended, not wider; the runtime tag check is the guard that matters.
- **The deploy policy's resource scoping is unverified against a real deploy.** Some actions it lists — `logs:DescribeLogGroups` among them — may not support resource-level scoping, in which case the `clamper*` resource pattern would make them fail rather than widen. Reports of a deploy that fails on a permission are welcome.
- **A scheduled resume undoes a Redshift clamp.** A cluster with a scheduled resume action comes back at its next run. Clamper does not change schedules; [`docs/actions.md`](docs/actions.md#redshift-clusters) says how to check for one.
- **No protect-tag `Deny` in IAM.** For ECS, Auto Scaling and Lambda the clamp and the release are the same IAM action, so a `Deny` on the protect tag would make a clamped resource unreleasable the moment somebody tagged it. Protect is enforced at runtime.
- **The enforcer has not yet run against a live account in CI.** Every handler is round-tripped against moto, and CloudFormation, S3, SNS and Cost Explorer calls are validated against the real service models with botocore's Stubber, but moto is not AWS.
- Prices in [`prices.yml`](src/clamper/data/prices.yml) are indicative us-east-1 on-demand list prices, used to rank what to show first. They need re-checking before each release.
